# 啵啵的房间

根据三张参考照片创作的 3D 风格虚拟角色与网页养成小游戏。角色名为啵啵。刚认识时是礼貌、有距离的陌生人，只能打招呼；熟悉之后才逐步接受照顾，傲娇和关心也会随关系增加。

用户已明确确认参考照片获得公开授权，并授权公开生成角色素材与上线小游戏。

[打开啵啵的房间](https://7-an.github.io/momo-room/)

此游戏纯为虚构。

## 关系与玩法

| 关系 | 累计亲密度 | 可用互动 |
| --- | ---: | --- |
| Lv. 1 陌生人 | 0 | 只能打招呼 |
| Lv. 2 点头之交 | 18 | 聊天、一起接星星 |
| Lv. 3 逐渐熟悉 | 42 | 加入带点心、送花、陪伴休息 |
| Lv. 4 亲近的朋友 | 66 | 加入摸摸 |
| Lv. 5 特别的默契 | 90 | 加入洗香香，全部互动开放 |

- 每个关系阶段只需 3 次有效招呼或聊天即可进入下一阶段；陪玩和其他已开放互动也能增加亲密度。陌生人每次打招呼获得 6 点亲密度；熟悉后聊天获得 8 点。每次间隔至少 3 秒，让上一句话说完。
- 初期点击角色只是打招呼，不会出现摸摸动作和爱心；Lv. 4 之后才可以点击或滑动抚摸。未解锁动作在页面和状态逻辑中均受限制，不会改变状态或发奖励。
- 白天、夜间房间、音效和名字设置不改变关系。原有存档的亲密度、星星糖、状态和自定义名字继续保留，旧默认名自动改成啵啵。
- 点心增加饱食度；睡觉每分钟恢复 4 点元气；接星星每局 15 秒，增加开心度、亲密度与星星糖，每局消耗 10 点元气，元气不足 30 时需要先休息或聊天。
- 每日心愿根据当天开始时的关系阶段安排，只使用当时已开放的互动。完成可额外获得 20 颗星星糖，同一天只领取一次；10 颗糖可送一束花，送礼需要 Lv. 3。
- 进度仅保存在当前浏览器的 localStorage，没有服务器、录音、账号或跨设备同步。清理浏览器数据会清除进度。
- 主要操作支持键盘和触屏。角色素材是 3D 渲染图像与动作动画，不是实时三维模型。

## 聊天、故事与回忆

- Lv. 1 保留单纯打招呼；Lv. 2 起可以选择「说说今天」「聊聊接星星」「安静坐一会儿」三个话题，每个话题有两个回答。回应随关系阶段改变，采用预写的虚构对白。打开、换话题或取消聊天不发奖励，实际回答按原聊天规则获得亲密度，仍有 3 秒间隔。
- 记住最近一次聊天选择；另一天打开或回到页面时，会接着问一句，当天不重复追问。这个续聊不增加亲密度。
- 首句招呼和进入 Lv. 2–5 时展开一页小剧情；聊天回答先读完、陪玩先退出，再显示剧情，不叠加弹窗。关系卡片可以重读当前阶段，相册可以重读已经发生的阶段故事。
- 「我们的回忆小册」保存带日期的小卡片：打招呼、聊天话题、一起玩、点心、礼物、睡眠、摸摸、洗香香和阶段变化。同一种回忆只记一次，不靠重复点击刷卡片，也不额外发奖励。
- 使用同一个浏览器存档键兼容旧进度；旧存档的等级、名字、星星糖和状态保留，回忆从更新后实际互动开始，不补造历史。相册仍只保存在本设备。
- 相册与剧情插画使用已有 SVG 图标和 CSS，不新增大图片或外部请求。

## 本地预览

无需安装依赖。在项目目录运行：

```bash
python3 -m http.server 4173 --bind 127.0.0.1
```

访问 `http://127.0.0.1:4173`。ES 模块需要 HTTP 服务，请不要直接双击 HTML 使用 `file://`。

## GitHub Pages

纯静态站点。将本仓库上传 GitHub，在 Settings → Pages 选择 Deploy from a branch，并选择 `codex/momo-room` 分支的 `/ (root)`。没有构建步骤或网络依赖。

## 文件

- `index.html`：页面结构、按钮与弹窗。
- `style.css`：房间、布局、响应式与动画。
- `app.js`：入口。读取存档、接上各界面模块、页面可见时定时更新与保存。
- `src/core/`：游戏规则，不操作页面，统一从 `src/core/index.js` 导入。
  - `state.js`：存档结构、`schema` 迁移、恢复校验、离线变化。
  - `relationship.js`：五个关系阶段、解锁等级与权限检查。
  - `care.js`：互动结算、每日心愿与聊天结算。
  - `journey.js`：回忆记录、去重与恢复。
- `src/content/`：文案。`dialogue.js` 是阶段语气与动作对白；`journey.js` 是阶段剧情、聊天话题与分支、回忆卡片和续聊。
- `src/persona/`：人设数据。`persona.js` 写喜好、雷点、观点、口头禅和作息；`index.js` 提供校验与查询（喜好匹配、某时刻在做什么、发现记录）。目前内容为占位版本，尚未接入玩法。
- `src/ui/`：界面。`session.js` 存档读写，`render.js` 画面，`actions.js` 互动反馈，`chat.js` 聊天，`stories.js` 剧情与回忆小册，`play.js` 接星星，`room.js` 按钮与触摸手势，另有 `dom.js`、`audio.js`、`effects.js`。
- `assets/character.webp`：网页优先加载的压缩四状态角色图。
- `assets/character.png`：保留的生成原图。
- `ASSET_PROMPT.md`：角色生成方式与完整提示词。
- `tests/`：使用 Node.js 22.7 或更新版本逐个运行：`model.test.mjs` 状态与奖励，`journey.test.mjs` 聊天、剧情与回忆，`save.test.mjs` 存档迁移与回滚兼容，`persona.test.mjs` 人设数据校验，`release.test.mjs` 检查所有模块的 `?v=` 缓存版本一致且路径可解析。

## 存档

- 存档键仍为 `momo-room-v1`，`version` 保持 `1`，这样回滚到旧版本时旧代码仍能读取进度。
- 结构变化记在 `schema` 字段，由 `src/core/state.js` 的 `migrate()` 逐级升级。当前 `schema` 为 2，比之前多了 `discoveries`（玩家已发现的人设喜好 id），旧存档迁移时为空，不补造。
- 新增结构时：提高 `SAVE_SCHEMA`，在 `migrations` 加一步，在 `freshState()` 与 `restoreState()` 补默认值和校验，并在 `tests/save.test.mjs` 加旧存档用例。
- 发布前改动任何 JS 都要把所有 `?v=` 一起换新，`release.test.mjs` 会检查漏改。
